## 2. คอนเซปต์

ผู้เล่นสแกน QR → ตอบคำถามเกี่ยวกับอนาคตของตัวเองบนมือถือ → ได้ **Avatar ห่าน 2.5D chibi** ที่ผูกกับผลคำตอบ

- Avatar ขึ้นจอใหญ่พร้อมชื่อ แล้วเดินเล่นบน Wall ร่วมกับคนอื่น
- ดาวน์โหลดการ์ด Avatar ขนาด 9:16 ไปแชร์ IG / TikTok ได้

**เป้าหมาย:** ดึงคนเข้าบูธ · ได้ภาพไปแชร์ต่อ · ได้สถิติว่าวัยรุ่นอยากเป็นอะไร เพื่อทำโพสต์หลังงาน

## 3. ลำดับการเล่น (เป้าหมาย ≤ 2 นาที)

1. สแกน QR → เปิดเว็บบนมือถือ (ไม่ต้องลงแอป)
2. ใส่ชื่อเล่น (ไม่เก็บข้อมูลส่วนตัวอื่น) + ข้อความแจ้ง PDPA
3. ตอบชุดคำถาม มีแถบความคืบหน้า
4. ระบบคำนวณผล + แอนิเมชันสั้น ๆ
5. หน้าผล: Avatar + ชื่อเล่น + ชื่อประเภท
6. ดาวน์โหลดการ์ด 9:16
7. Avatar ขึ้น Spotlight บนจอใหญ่ แล้วเดินลงไปอยู่ใน Wall

## 4. เนื้อหาที่ผู้จัดทำต้องเตรียม

- [ ] คำถามและตัวเลือก
- [ ] วิธีจับคู่คำตอบกับ Avatar (ให้คะแนน หรือผูกตรง ๆ)
- [ ] กติกาเมื่อผลเสมอ
- [ ] ชื่อประเภท + ข้อความสั้นของแต่ละ Avatar

> ช่วงพัฒนา ระบบใช้ **คำถามและ Avatar ชั่วคราว (placeholder)** เก็บไว้ในไฟล์เดียว เปลี่ยนเป็นของจริงได้โดยไม่แก้โค้ดส่วนอื่น

- [ ] อุปกรณ์ประกอบแยกไฟล์ (เช่น จรวด) - ถ้ามี

## 5. หน้าจอใหญ่ (แนวตั้ง 1080 × 1920)

| ส่วน      | สัดส่วน | เนื้อหา                                     |
| --------- | ------- | ------------------------------------------- |
| หัวจอ     | ~10%    | FUTURE WALL                                 |
| Spotlight | ~45%    | Avatar ใหญ่ + ชื่อ + ประเภท ค้าง 5–8 วินาที |
| Wall      | ~35%    | Avatar ทุกตัวเดินสุ่ม                       |
| ท้ายจอ    | ~10%    | ตัวนับแต่ละประเภท + QR "สแกนเล่นเลย!"       |

**พฤติกรรม**

- คนเล่นใหม่: ขึ้น Spotlight แล้วย่อตัวเดินลง Wall
- หลายคนพร้อมกัน: ต่อคิว Spotlight ทีละคน
- การเดิน: สุ่มทิศ · เด้งขึ้นลง + โยก · พลิกภาพเมื่อกลับทิศ · ย่อขยายตามความลึก (2.5D) · หยุดพักด้วยท่ายืน
- จำนวนบนจอ ≤ ~40 ตัว ตัวเก่าค่อยจางหาย (ข้อมูลยังอยู่)
- ไม่มีคนเล่น: วนโชว์ Avatar ทุกประเภท + สุ่มดึงผู้เล่นเก่ากลับ Spotlight

## 6. การจัดบูธ 2 × 2 ม.

- **ผนังหลัง:** ฉากแบรนด์ + จอแนวตั้ง 55" ตรงกลาง
- **มุมข้าง:** โต๊ะเล็ก คอมพิวเตอร์ เราเตอร์ สตาฟ 1 คน
- **ด้านหน้า:** ป้ายตั้ง QR + สติกเกอร์พื้นจุดยืนถ่ายรูป

**อุปกรณ์:** จอ 55" + ขาตั้ง · Mini PC/โน้ตบุ๊ก (เบราว์เซอร์เต็มจอ) + เครื่องสำรอง · Pocket WiFi/4G สำรอง · ปลั๊กพ่วง + HDMI สำรอง · ลำโพงเล็ก (ถ้าใช้เสียง) · ป้าย QR / ฉากหลัง / สติกเกอร์พื้น

## 7. ระบบ (ฉบับปรับปรุง)

| ส่วน                  | เทคโนโลยี                                                                                            |
| --------------------- | ---------------------------------------------------------------------------------------------------- |
| Framework             | **Nuxt 4** (Vue 3, `<script setup>`, TypeScript) ตาม repo นี้                                        |
| สไตล์                 | UnoCSS + CSS animation / Canvas                                                                      |
| เรียลไทม์ + ฐานข้อมูล | **Supabase** (Postgres + Realtime)                                                                   |
| การ์ดดาวน์โหลด        | Canvas บนมือถือ → PNG 1080 × 1920                                                                    |
| Hosting               | Netlify / Vercel (มี `netlify.toml` อยู่แล้ว)                                                        |
| โหมดสำรอง             | ถ้ายังไม่ตั้งค่า Supabase ใช้ **demo mode** (localStorage + BroadcastChannel) เพื่อลองบนเครื่องเดียว |

### หน้าเว็บ

1. `/` หน้าเล่นบนมือถือ: ชื่อ → คำถาม → ผล → ดาวน์โหลด
2. `/wall` หน้าจอใหญ่
3. `/admin` หน้าสตาฟ: ซ่อน/ลบผู้เล่น, รีเซ็ตจอ, ดูสถิติ (ต้องใส่ PIN)

### ข้อมูลที่เก็บ

`{ id, nickname, avatarType, answers[], hidden, createdAt }` - ไม่เก็บข้อมูลส่วนตัวอื่น

### ตั้งค่า Supabase (ต้องทำโดยเจ้าของโปรเจกต์)

- [ ] สร้างโปรเจกต์ Supabase แล้วรัน SQL ใน `docs/supabase.sql`
- [ ] ใส่ `NUXT_PUBLIC_SUPABASE_URL`, `NUXT_PUBLIC_SUPABASE_ANON_KEY` ใน `.env`
- [ ] ตั้ง `NUXT_ADMIN_PIN` ใน `.env` (PIN สตาฟ)

## 8. ความเสี่ยงและแผนรับมือ
